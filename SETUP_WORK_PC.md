# Настройка нового (рабочего) ПК — инструкция для чайника

Чистая Windows-машина → CRM работает в браузере. Нужно сделать **5 шагов**.
Каждый шаг: что открыть, что напечатать, что увидеть в итоге.

---

## Шаг 1. Установить 3 программы

Открыть **Пуск → PowerShell → правой кнопкой → «Запуск от имени администратора»**.

Вставлять по одной команде, ждать конца каждой:

```powershell
winget install --id Git.Git -e --source winget
```

```powershell
wsl --install
```

```powershell
winget install --id Docker.DockerDesktop -e --source winget
```

**Перезагрузить ПК** (обязательно, после WSL).

После перезагрузки: запустить **Docker Desktop** с рабочего стола и подождать,
пока в трее у иконки кита не появится надпись про работающий движок
(1–3 минуты, первый запуск дольше).

> Python и Node ставить не нужно — всё работает внутри Docker.
> Если `winget` пишет «не найдено» — установщики вручную:
> git-scm.com/download/win, docker.com/products/docker-desktop.

**Проверка**: открыть PowerShell (обычный, не админский) и напечатать
`docker version` — должны увидеть номера версий, а не ошибку.

---

## Шаг 2. Скачать код проекта

Обычный PowerShell (не админский):

```powershell
mkdir C:\Github
cd C:\Github
git clone https://github.com/shaurum/bike-crm-api.git
cd bike-crm-api
```

Репозиторий приватный — всплывёт окно входа в GitHub. Войти под аккаунтом
`shaurum` (или попросить пригласить свой аккаунт в репозиторий).

**Проверка**: команда `dir` показывает папки `backend`, `frontend`, `scripts`.

---

## Шаг 3. Положить файл секретов (.env)

Файл `.env` с паролями **не хранится в git** — его копируют со старого ПК.

Со **старого ПК** скопировать файл:
`F:\Github\bike-crm-api\.env`

На **новом ПК** вставить сюда (в проводнике, в папку `C:\Github\bike-crm-api`):
```
C:\Github\bike-crm-api\.env
```

Если старого ПК нет — создать пустой файл `.env` и заполнить по шаблону
`.env.example` (без секретов интеграции CRM запустится, просто Авито/Telegram
и почта не будут работать).

### 3б. Токен для автообновления (GITHUB_TOKEN)

Внутри файла `.env` должна быть строка (без пробелов вокруг `=`):

```
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxx
```

Как получить токен (делается один раз на любом ПК):
1. Открыть https://github.com/settings/tokens?type=beta (Fine-grained tokens)
2. «Generate new token»
3. Repository access → **Only select repositories** → `shaurum/bike-crm-api`
4. Permissions → Repository permissions → **Contents: Read-only** (всё остальное не трогать)
5. Срок жизни: например, 1 год
6. Скопировать токен (после закрытия окна он больше не покажется) и вписать
   в `.env` строку `GITHUB_TOKEN=...`

Без этого токена CRM заработает, но обновления качать не сможет.

## Шаг 4. Запустить всё одной командой

```powershell
cd C:\Github\bike-crm-api
powershell -ExecutionPolicy Bypass -File scripts\setup-new-pc.ps1
```

Ждать 3–10 минут (первая сборка образов — самая долгая часть).
Скрипт сам: проверит Docker → подложит `.env` → соберёт и запустит все
сервисы → применит миграции БД → зарегистрирует автообновление.

В конце должно появиться:
```
Done!
  CRM:      http://localhost:3000
```

**Если что-то упало** — скопировать текст ошибки целиком (или сделать скриншот)
и разобраться; почти всегда помогает перезапуск Docker Desktop и повтор шага 4.

---

## Шаг 5. Первый вход в CRM

1. Открыть браузер: **http://localhost:3000/register**
2. Зарегистрировать **первого** пользователя — он автоматически станет
   администратором. E-mail указывать настоящий рабочий.
3. Дальше вход: **http://localhost:3000/login**

Готово. Данные лежат на этом ПК (папка `data/`), сотрудников добавлять
пригласительными ссылками из раздела **Пользователи**.

## Что дальше: автообновления

Настроены автоматически (задача Windows «BikeCrmAutoUpdate», каждые 5 минут):

- Выпустить новую версию = на разработческом ПК сделать `git tag vX.Y.Z`
  и `git push origin vX.Y.Z` — на всех рабочих ПК обновление приедет само.
- Последняя версия и статус: в CRM **Настройки → Обновление**.
- Там же галка: **«Авто»** — ставить сразу; **«Вручную»** — ставить только
  по кнопке «Проверить и установить».
- Возврат на прошлую версию: выпустить тег прошлой версии заново.
- Ручная проверка без ожидания: PowerShell в папке проекта
  `powershell -ExecutionPolicy Bypass -File scripts\auto-update.ps1`

## Если что-то не так

| Симптом | Что делать |
|---------|-----------|
| `docker` не найден | ПК перезагрузили после установки WSL? Docker Desktop запущен? |
| Docker запущен, но `docker version` ругается | подождать полной загрузки Docker Desktop (tray-иконка) |
| `port is already allocated` | порт занят: `netstat -ano \| findstr :3000` → закрыть мешающую программу |
| Страница http://localhost:3000 не открывается | `docker compose ps` — все контейнеры должны быть Up; если нет — повторить шаг 4 |
| В CRM «нет GITHUB_TOKEN в .env» | пропущен шаг 3б |
| Вышел новый релиз, а CRM не обновилась | Настройки → Обновление → галка «Авто» либо кнопка «Проверить и установить»; или запустить `scripts\auto-update.ps1` вручную и посмотреть текст |
| Код менялся прямо на этом ПК и автообновление пишет «есть локальные изменения» | это защита от затирания правок; если правки не нужны: `git checkout -- .`; если нужны, но надо обновиться: `scripts\auto-update.ps1 -Apply` (правки сотрутся) |
| Не проходит `git clone` / `git push` | `git config --global credential.helper manager` и войти в GitHub в появившемся окне |
